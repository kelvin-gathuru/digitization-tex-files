\subsection*{Module Overview}
This module extends the attention and Transformer machinery from Module 3 into computer vision. You will explore the \textbf{Vision Transformer (ViT)}, which treats an image as a sequence of patches and processes it with an otherwise-unmodified Transformer encoder, and examine the broader landscape of \textbf{visual representation learning} it belongs to: methods for learning general-purpose image features from data, with or without labels. We cover \textbf{self-supervised and contrastive learning} methods that learn from unlabeled images, \textbf{multimodal foundation models} such as \textbf{CLIP} that learn joint image-text representations from web-scale data, and \textbf{Attention Rollout}, a method for interpreting what a trained Vision Transformer is actually looking at. 
\end{tcolorbox}

\section{Introduction to Vision Transformers and Visual Representation Learning}
% ============================================================

\subsection{From Convolutions to Attention}

For nearly a decade, convolutional neural networks (CNNs) were the dominant architecture for computer vision, owing to two built-in \textbf{inductive biases} well-suited to images:

\begin{itemize}[leftmargin=1.5em]
    \item \textbf{Locality:} A convolutional filter only looks at a small local neighborhood of pixels at a time, reflecting the fact that nearby pixels are usually more related than distant ones.
    \item \textbf{Translation equivariance:} The same filter weights are applied at every spatial location, so a shifted input produces a correspondingly shifted output -- a natural fit for recognizing an object regardless of where it appears in the image.
\end{itemize}

\begin{keyidea}
These inductive biases are a double-edged sword: they make CNNs highly \textbf{data-efficient} (a useful prior is built directly into the architecture, so less data is needed to discover it from scratch), but they also \emph{limit} what the network can easily represent -- a single convolutional layer can only relate nearby pixels, and modeling long-range dependencies (e.g., relating one corner of an image to another) requires stacking many layers to gradually grow the receptive field. The \textbf{Vision Transformer (ViT)} (Dosovitskiy et al., 2020) asks: what if we remove these hand-built biases almost entirely, and let a Transformer -- with self-attention's inherent ability to relate \emph{any} two positions in a single layer (Module 3) -- learn whatever spatial structure is useful directly from data?
\end{keyidea}

\subsection{The Central Trade-off: Inductive Bias vs.\ Scale}

\begin{keyidea}
ViT's original paper reported that, when trained on a mid-sized dataset like ImageNet-1k alone, a pure Transformer underperforms a comparable CNN -- consistent with the idea that the CNN's built-in locality/equivariance biases are genuinely useful when data is limited. However, when pretrained on much larger datasets (tens to hundreds of millions of images), ViT matches or exceeds CNN performance, since with enough data, the network can learn useful spatial priors on its own, and having \emph{fewer} hard-coded assumptions leaves \emph{more} capacity available to discover patterns a human-designed architecture might not have anticipated. This established a now-common theme in modern deep learning: architectures with weaker inductive biases but higher capacity tend to win out \emph{given enough data and compute}, a pattern also seen when Transformers overtook RNNs in NLP (Module 3).
\end{keyidea}

\subsection{What Is Visual Representation Learning?}

\begin{defbox}
\textbf{Visual representation learning} is the study of how to learn general-purpose image embeddings -- vector representations of images (or image patches/regions) -- that capture useful visual and semantic structure, in a way that transfers well to \emph{many} downstream tasks (classification, detection, segmentation, retrieval, captioning), rather than being tailored to a single task from the start.
\end{defbox}

\begin{keyidea}
A recurring theme of this module is that \emph{how} a representation is learned -- supervised on labeled classes, self-supervised on unlabeled images alone, or contrastively aligned with natural-language descriptions -- has a major effect on what kind of downstream tasks the resulting representation transfers well to, and how much labeled data (if any) is needed to adapt it. This module surveys the major paradigms in roughly the order they build on one another: architecture (ViT), self-supervised/contrastive pretraining objectives, and multimodal foundation models.
\end{keyidea}

\section{Patch Embeddings and the Transformer Encoder Architecture}
% ============================================================

The core challenge in applying a Transformer to images is representational: Module 3's Transformer operates on a \emph{sequence} of token vectors, but an image is a 2D (or 3D, with channels) grid of pixels. ViT's solution is to convert the image into a sequence of \textbf{patch embeddings} and then apply an otherwise-standard Transformer encoder.

\subsection{Patchify and Linear Projection}

\begin{defbox}
Given an input image $x \in \mathbb{R}^{H\times W\times C}$, ViT first splits it into a grid of $N = \frac{HW}{P^2}$ non-overlapping square \textbf{patches}, each of size $P \times P \times C$ (e.g., $P=16$). Each patch is flattened into a vector of length $P^2 C$, and linearly projected into a $D$-dimensional \textbf{patch embedding}:
\[
z_i = E \cdot \text{flatten}(x_i) + b, \qquad i = 1, \ldots, N
\]
where $E \in \mathbb{R}^{D \times P^2C}$ is a learned projection matrix (shared across all patches).
\end{defbox}

\begin{keyidea}
This patchify-and-project operation is mathematically identical to a single convolutional layer with kernel size $P\times P$ and stride $P$ (a non-overlapping ``strided'' convolution) -- ViT's very first operation is, in fact, a small convolution, and the ``pure Transformer, no convolutions'' framing really refers to everything \emph{after} this initial patch embedding step. Choosing a smaller patch size $P$ increases the number of patches $N$ (finer spatial resolution, but quadratically more expensive self-attention, since attention costs $O(N^2D)$ as established in Module 3), while a larger $P$ is cheaper but coarser -- a direct, tunable trade-off between resolution and compute.
\end{keyidea}

\subsection{The Classification Token}

\begin{defbox}
Following the BERT convention from NLP, ViT prepends a special, learnable \textbf{classification token} embedding $z_{cls}$ to the sequence of patch embeddings, so the input to the Transformer encoder is $[z_{cls}, z_1, \ldots, z_N]$. After passing through the full encoder, the \emph{final} representation of this token, $z_{cls}^{(L)}$, is used as the aggregate, whole-image representation for downstream classification.
\end{defbox}

\begin{keyidea}
Because self-attention lets every token attend to every other token, the $[\text{CLS}]$ token can, over the course of the encoder's layers, gather and aggregate information from every patch in the image into a single vector -- serving the same role that global average pooling serves at the end of a CNN, but learned and content-dependent (via attention) rather than a fixed, uniform average.
\end{keyidea}

\subsection{Positional Embeddings}

Self-attention alone is permutation-equivariant and has no notion of \emph{where} each patch is located in the image. ViT adds a learned \textbf{positional embedding} $E_{pos}$ to each patch embedding (and to the $[\text{CLS}]$ token) before the first encoder layer:
\[
z_0 = [z_{cls} + E_{pos}^{(0)},\; z_1 + E_{pos}^{(1)}, \ldots, z_N + E_{pos}^{(N)}]
\]

\begin{keyidea}
Unlike the fixed sinusoidal positional encoding often used in NLP Transformers, ViT typically uses \emph{learned} 1-D positional embeddings (one per patch index, with no explicit 2-D spatial structure hard-coded), and the model is left to discover any useful 2-D spatial relationships (e.g., ``adjacent row/column'') on its own during training -- another example of ViT's general philosophy of minimizing hard-coded assumptions in favor of letting the data determine what structure matters.
\end{keyidea}

\subsection{The Transformer Encoder}

\begin{defbox}
The sequence of (position-augmented) patch embeddings is passed through $L$ standard Transformer encoder layers, exactly as defined in Module 3: each layer applies multi-head self-attention followed by a position-wise MLP, each wrapped in a residual connection and layer normalization:
\[
z_\ell' = z_{\ell-1} + \text{MSA}(\text{LN}(z_{\ell-1})), \qquad z_\ell = z_\ell' + \text{MLP}(\text{LN}(z_\ell'))
\]
\end{defbox}

\begin{keyidea}
ViT uses the \textbf{Pre-LN} convention (layer normalization applied \emph{before} each sublayer, rather than after, as discussed in Module 3), which was found to produce more stable training, particularly important for very deep ViT variants. Aside from this convention and the patch-embedding front-end, ViT's encoder is architecturally identical to a text Transformer encoder -- underscoring that, once an image has been converted into a sequence of vectors, the rest of the machinery from Module 3 transfers directly, with no vision-specific modification required.
\end{keyidea}

\subsection{Classification Head and Model Variants}

A final MLP head (typically a single linear layer during fine-tuning, or an MLP with one hidden layer during pretraining) maps the final $[\text{CLS}]$ representation $z_{cls}^{(L)}$ to class logits. ViT is commonly instantiated at several standard sizes (ViT-Base, ViT-Large, ViT-Huge), differing in embedding dimension $D$, depth $L$, and number of attention heads -- directly analogous to how BERT/GPT-style text Transformers are scaled.

\subsection{Data-Efficient Variants: DeiT}

\begin{keyidea}
Since ViT's lack of convolutional inductive bias makes it data-hungry, \textbf{DeiT} (Data-efficient Image Transformers, Touvron et al., 2021) showed that a ViT can be trained effectively on a much smaller dataset (ImageNet-1k alone) using stronger data augmentation, regularization, and a \textbf{distillation token}: an additional special token trained to match the predictions of a pretrained CNN ``teacher'' model via knowledge distillation. This demonstrates that ViT's data-hungriness is a property of the \emph{training recipe}, not an immovable property of the architecture itself.
\end{keyidea}

\section{Self-Supervised and Contrastive Learning Methods}
% ============================================================

Labeled data is expensive to collect at scale, while unlabeled images are abundant. \textbf{Self-supervised learning (SSL)} designs a \textbf{pretext task} -- a task with automatically-generatable ``labels'' derived from the data itself -- so a network can learn useful representations from unlabeled images alone, which can then transfer to downstream tasks via fine-tuning or linear probing.

\subsection{The Contrastive Learning Framework}

\begin{defbox}
\textbf{Contrastive learning} trains an encoder so that representations of two different \textbf{augmented views} of the \emph{same} image (a \textbf{positive pair}) are pulled close together in embedding space, while representations of views from \emph{different} images (\textbf{negative pairs}) are pushed apart.
\end{defbox}

\begin{keyidea}
The pretext task here is implicit: an encoder cannot easily learn to recognize that two heavily and differently augmented crops (e.g., different crop regions, color distortions, blurring) came from the same underlying image unless it learns to focus on the image's actual semantic content (the object present), rather than low-level, augmentation-sensitive pixel statistics -- which is exactly the kind of representation that tends to transfer well to downstream recognition tasks.
\end{keyidea}

\subsection{SimCLR}

\textbf{SimCLR} (Chen et al., 2020) is a conceptually simple, influential contrastive framework:

\begin{enumerate}[leftmargin=1.5em]
    \item Given an image, generate two randomly augmented views (random crop, color jitter, Gaussian blur, etc.).
    \item Pass both views through a shared encoder $f(\cdot)$, then a small \textbf{projection head} MLP $g(\cdot)$, producing embeddings $z_i, z_j$.
    \item Within a training batch of $N$ images (yielding $2N$ augmented views), treat the other view of the same image as the single positive, and all other $2(N-1)$ views in the batch as negatives, minimizing the \textbf{NT-Xent} (normalized temperature-scaled cross-entropy) loss:
\[
\ell_{i,j} = -\log \frac{\exp(\text{sim}(z_i,z_j)/\tau)}{\sum_{k=1}^{2N} \mathbb{1}_{[k\neq i]}\exp(\text{sim}(z_i,z_k)/\tau)}
\]
where $\text{sim}(\cdot,\cdot)$ is cosine similarity and $\tau$ is a temperature hyperparameter.
\end{enumerate}

\begin{keyidea}
SimCLR's loss is directly analogous to a softmax classification loss where the ``correct class'' is the matching positive view among $2N-1$ candidates -- and because \emph{every other view in the batch} serves as a negative, SimCLR's performance is strongly dependent on using a \textbf{very large batch size} (thousands of images) to provide enough negatives for the contrastive signal to be informative, which is computationally demanding.
\end{keyidea}

\subsection{MoCo: Decoupling Negatives from Batch Size}

\begin{defbox}
\textbf{MoCo} (Momentum Contrast, He et al., 2020) addresses SimCLR's large-batch requirement by maintaining a large \textbf{queue} of negative embeddings computed from \emph{previous} batches, decoupling the number of available negatives from the current batch size. To keep these queued embeddings consistent with the current encoder (since the encoder is continually changing), MoCo uses a \textbf{momentum encoder}: a second copy of the encoder whose weights $\theta_k$ are updated as a slow exponential moving average of the main (query) encoder's weights $\theta_q$: $\theta_k \leftarrow m\theta_k + (1-m)\theta_q$, with $m$ close to 1 (e.g., 0.999).
\end{defbox}

\begin{keyidea}
The momentum encoder is a direct conceptual cousin of DQN's target network: both address the problem of needing a \emph{slowly-changing, stable} reference to compare against, while the main network being trained changes rapidly at every step. This lets MoCo maintain a queue of tens of thousands of negatives that remain reasonably consistent with each other, without needing an enormous batch size.
\end{keyidea}

\subsection{BYOL: Contrastive Learning Without Negatives}

\begin{keyidea}
\textbf{BYOL} (Bootstrap Your Own Latent, Grill et al., 2020) makes a striking claim: negative pairs are not actually necessary at all. BYOL trains an \textbf{online network} to directly \emph{predict} the output of a \textbf{target network} (a momentum-updated copy of the online network, as in MoCo) applied to a differently-augmented view of the same image -- using only positive pairs. Naively, this setup risks \textbf{representation collapse} (the trivial solution of mapping every input to the same constant vector perfectly satisfies a positive-only matching objective), which BYOL avoids through a combination of architectural asymmetry (an extra \textbf{predictor} MLP on the online branch only) and the momentum target network, without any explicit negative examples or repulsive term in the loss.
\end{keyidea}

\subsection{Masked Image Modeling: MAE}

Inspired directly by masked language modeling (Module 3's BERT-style pretraining), \textbf{Masked Autoencoders (MAE)} (He et al., 2022) apply a masking-and-reconstruction pretext task to images.

\begin{defbox}
MAE randomly masks a very large fraction (e.g., 75\%) of an image's patches. A ViT \textbf{encoder} processes \emph{only the small number of visible (unmasked) patches} (a major efficiency advantage, since self-attention's cost scales with sequence length). A lightweight \textbf{decoder} then takes the encoded visible patches plus mask tokens (placeholder embeddings marking masked positions) and is trained to reconstruct the raw pixel values of the masked patches.
\end{defbox}

\begin{keyidea}
Masking such a high fraction of patches is deliberate and important: with images (unlike text), nearby pixels are highly redundant, so masking only a small fraction (as BERT does with words, around 15\%) would make the reconstruction task too easy to solve using simple local interpolation, without requiring the network to learn genuinely high-level semantic understanding. A very high masking ratio forces the encoder to build a representation rich enough to support reconstructing large missing regions purely from sparse visible context.
\end{keyidea}

\subsection{DINO: Self-Distillation with No Labels}

\textbf{DINO} (Caron et al., 2021) trains a student ViT to match the output of a momentum-updated teacher ViT, applied to different augmented crops of the same image (architecturally similar in spirit to BYOL), using a self-distillation cross-entropy loss with careful centering and sharpening to avoid collapse. A striking empirical finding: DINO's self-attention maps, with no supervision or labels whatsoever, spontaneously learn to focus sharply on the semantic foreground objects in an image -- a property exploited directly by the interpretability technique in Section 5.

\section{Multimodal and Foundation Vision Models: CLIP and Foundational Image Pretraining}
% ============================================================

\subsection{Foundation Models: The General Paradigm}

\begin{defbox}
A \textbf{foundation model} is a model pretrained on broad, large-scale data, designed to be \textbf{adapted} (via fine-tuning, linear probing, prompting, or zero-shot transfer) to a wide range of downstream tasks, rather than being trained for one specific task from the start. The self-supervised methods of Section 3 already embody part of this idea (learning general-purpose features from broad, unlabeled image data); this section studies models that push the paradigm further by incorporating \textbf{natural language} as a second modality.
\end{defbox}

\subsection{CLIP: Contrastive Language-Image Pretraining}

\textbf{CLIP} (Radford et al., 2021) learns a \emph{joint} embedding space for images and text by training on hundreds of millions of (image, caption) pairs collected from the web, using a contrastive objective directly analogous to Section 3's contrastive methods, but \emph{across modalities} rather than across augmented views of the same image.

\subsubsection{Architecture}

\begin{itemize}[leftmargin=1.5em]
    \item An \textbf{image encoder} (a ViT or a CNN such as ResNet) maps an image to an embedding $v \in \mathbb{R}^d$.
    \item A \textbf{text encoder} (a Transformer, as in Module 3) maps a caption to an embedding $t \in \mathbb{R}^d$.
    \item Both embeddings are projected into the \emph{same} shared $d$-dimensional space and $L_2$-normalized.
\end{itemize}

\subsubsection{Training Objective}

\begin{defbox}
Given a batch of $N$ (image, text) pairs, CLIP computes the cosine similarity between every image embedding and every text embedding in the batch, forming an $N\times N$ similarity matrix. It is trained with a symmetric contrastive loss (InfoNCE-style, directly analogous to SimCLR's NT-Xent loss in Section 3) that maximizes the similarity of each image with its \emph{correct, matching} caption (the diagonal of the matrix) relative to all $N-1$ \emph{other, non-matching} captions in the batch (the off-diagonal entries), and symmetrically for each caption relative to all other images.
\end{defbox}

\begin{keyidea}
CLIP's key insight is that natural-language captions provide a vastly richer and more flexible source of supervision than a fixed, predetermined set of class labels (as in traditional supervised ImageNet pretraining): captions can describe virtually unlimited visual concepts, attributes, and relationships, in whatever vocabulary happens to appear in web text, rather than being restricted to (for example) exactly 1000 ImageNet categories decided in advance by the dataset's creators.
\end{keyidea}

\subsubsection{Zero-Shot Classification}

\begin{keyidea}
Because CLIP's image and text embeddings share a common space, it can classify images into \emph{any} set of candidate classes \textbf{without any task-specific fine-tuning}: construct a text prompt for each candidate class (e.g., ``a photo of a \{class name\}''), embed all candidate prompts with the text encoder, embed the query image with the image encoder, and predict the class whose text embedding has the highest cosine similarity to the image embedding. This \textbf{zero-shot transfer} capability -- performing a new classification task specified only by a list of class names, with no labeled training examples for that specific task -- was one of CLIP's most striking and influential results, showing competitive performance with fully-supervised models trained specifically on some of these benchmarks.
\end{keyidea}

\begin{example}
To classify an image as one of \{``cat'', ``dog'', ``car''\} using CLIP with no fine-tuning: form the prompts ``a photo of a cat'', ``a photo of a dog'', ``a photo of a car''; compute their text embeddings $t_1, t_2, t_3$ and the image's embedding $v$; predict $\arg\max_i \cos(v, t_i)$. If $\cos(v,t_1) = 0.31$, $\cos(v,t_2) = 0.24$, $\cos(v,t_3) = 0.08$, the predicted class is ``cat''. Note that entirely new candidate classes could be added at inference time simply by writing a new prompt, with no retraining required.
\end{example}

\subsection{Foundational Image Pretraining}

CLIP is one prominent instance of a broader trend of training large \textbf{vision foundation models} on internet-scale data, using a variety of pretraining recipes, each producing representations with somewhat different strengths:

\begin{itemize}[leftmargin=1.5em]
    \item \textbf{Supervised pretraining} (e.g., classic ImageNet-1k pretrained CNNs/ViTs): strong, well-understood features, but tied to the specific label vocabulary used during training.
    \item \textbf{Self-supervised pretraining} (Section 3: SimCLR, MoCo, BYOL, MAE, DINO): learns from unlabeled images alone; DINOv2 (Oquab et al., 2023) scaled this recipe substantially, producing general-purpose visual features that transfer well to dense prediction tasks (depth estimation, segmentation) even \emph{without} any fine-tuning, via simple linear probes.
    \item \textbf{Contrastive language-image pretraining} (CLIP and successors, e.g., ALIGN, OpenCLIP): learns a joint vision-language space directly from naturally-occurring web image-text pairs, enabling zero-shot transfer and serving as a foundation for later multimodal systems.
    \item \textbf{Promptable foundation models} (e.g., the Segment Anything Model, SAM, Kirillov et al., 2023): trained on a very large, diverse segmentation dataset to segment \emph{any} object given a prompt (a point, box, or rough mask) at inference time, generalizing to novel objects and image types not seen during training.
\end{itemize}

\begin{keyidea}
A unifying theme across all of these is the same \textbf{pretrain-then-adapt} paradigm introduced at the start of this section: invest heavily in a single, broad, large-scale pretraining phase, and then adapt the resulting representation cheaply (via zero-shot prompting, linear probing, or lightweight fine-tuning) to many different downstream tasks -- rather than training a separate, task-specific model from scratch for every new application, which is far more data- and compute-expensive.
\end{keyidea}

\section{Attention Rollout}
% ============================================================

Having studied how ViTs are trained (Sections 2--4), we now turn to \textbf{interpreting} what a trained ViT has actually learned to attend to -- specifically, which input image patches most influence its final prediction.

\subsection{Why Raw Attention Maps Are Insufficient}

\begin{keyidea}
A natural first idea is to simply visualize the attention weights from the \emph{final} layer's $[\text{CLS}]$ token row: this directly shows which patches the last layer attended to. However, this ignores everything that happened in \emph{earlier} layers: information reaching the final layer's attention computation has already been mixed and re-mixed across all previous layers (and residual connections additionally let a token's original identity persist alongside whatever attention has mixed in). A patch that was highly influential in shaping an intermediate representation two layers back, but is not directly attended to by the very last layer, would be invisible in a raw last-layer attention map, even though it substantially influenced the final output.
\end{keyidea}

\subsection{The Attention Rollout Method}

\textbf{Attention Rollout} (Abnar \& Zuidema, 2020) addresses this by tracking how attention (and the residual/skip-connection pathway) propagates information \emph{across all layers}, from the input patches all the way to the final representation.

\begin{defbox}
For each layer $\ell$, let $A_\ell \in \mathbb{R}^{N\times N}$ be the attention matrix (averaged across heads), where $A_\ell[i,j]$ is the attention weight from token $i$ to token $j$. To account for the residual connection at each layer (which lets a token's representation flow forward \emph{unchanged}, in addition to whatever it gathers via attention), define the \textbf{augmented attention matrix}:
\[
\hat{A}_\ell = 0.5 A_\ell + 0.5 I
\]
where $I$ is the identity matrix, and each row is re-normalized to sum to 1. \textbf{Attention Rollout} is then computed as the matrix product of these augmented attention matrices across all $L$ layers:
\[
\text{Rollout} = \hat{A}_L \cdot \hat{A}_{L-1} \cdots \hat{A}_1
\]
\end{defbox}

\begin{keyidea}
The $0.5A_\ell + 0.5I$ construction directly models the residual connection: with probability (weight) $0.5$, a token's information at this layer is a function of its attention-weighted mixture with other tokens ($A_\ell$); with the other $0.5$, it simply passes through unchanged (the identity term). Multiplying these augmented matrices together, layer by layer, tracks how ``credit'' or information flow from every original input patch is diluted, mixed, and propagated forward through the \emph{entire} depth of the network -- rather than looking at any single layer in isolation. The row of the final Rollout matrix corresponding to the $[\text{CLS}]$ token gives a distribution over input patches representing their aggregate contribution to the final classification decision, which can be reshaped back into the image's spatial grid and visualized as a heatmap overlaid on the original image.
\end{keyidea}

\subsection{Worked Example}

\begin{example}
Consider a toy 2-layer, 2-token ($[\text{CLS}]$ and one patch) Transformer for simplicity. Suppose the raw attention matrices (rows sum to 1, row/column order is [$\text{CLS}$, patch]) are:
\[
A_1 = \begin{pmatrix} 0.6 & 0.4 \\ 0.3 & 0.7 \end{pmatrix}, \qquad
A_2 = \begin{pmatrix} 0.5 & 0.5 \\ 0.2 & 0.8 \end{pmatrix}
\]
First, augment each with the identity and re-normalize ($0.5A_\ell + 0.5I$, rows already sum to 1 since $A_\ell$'s rows do and $I$'s rows do):
\[
\hat A_1 = 0.5\begin{pmatrix} 0.6 & 0.4 \\ 0.3 & 0.7 \end{pmatrix} + 0.5\begin{pmatrix} 1 & 0 \\ 0 & 1 \end{pmatrix} = \begin{pmatrix} 0.8 & 0.2 \\ 0.15 & 0.85 \end{pmatrix}
\]
\[
\hat A_2 = 0.5\begin{pmatrix} 0.5 & 0.5 \\ 0.2 & 0.8 \end{pmatrix} + 0.5\begin{pmatrix} 1 & 0 \\ 0 & 1 \end{pmatrix} = \begin{pmatrix} 0.75 & 0.25 \\ 0.1 & 0.9 \end{pmatrix}
\]
Computing Rollout $= \hat A_2 \cdot \hat A_1$:
\begin{align*}
\text{Rollout} &= \begin{pmatrix} 0.75 & 0.25 \\ 0.1 & 0.9 \end{pmatrix}\begin{pmatrix} 0.8 & 0.2 \\ 0.15 & 0.85 \end{pmatrix} \\[0.5em]
&= \begin{pmatrix} (0.75)(0.8)+(0.25)(0.15) & (0.75)(0.2)+(0.25)(0.85) \\ (0.1)(0.8)+(0.9)(0.15) & (0.1)(0.2)+(0.9)(0.85) \end{pmatrix} \\[0.5em]
&= \begin{pmatrix} 0.6375 & 0.3625 \\ 0.215 & 0.785 \end{pmatrix}
\end{align*}
Reading the $[\text{CLS}]$ row (first row): the final classification decision's rollout attention attributes $63.75\%$ of its aggregate attention to the $[\text{CLS}]$ token itself (i.e., its own persisting identity via residual connections) and $36.25\%$ to the single patch token, across both layers combined.
\end{example}

\subsection{Relation to Other Interpretability Methods}

\begin{itemize}[leftmargin=1.5em]
    \item \textbf{Raw last-layer attention:} Simpler, but (as discussed above) ignores multi-layer information mixing and residual pathways.
    \item \textbf{Gradient-based saliency methods} (e.g., Grad-CAM, originally developed for CNNs): Use gradients of the output with respect to intermediate activations to estimate the importance of different spatial regions; conceptually different from attention rollout, which relies purely on the (already-computed) attention weights themselves, without needing an additional backward pass.
    \item \textbf{DINO's emergent attention maps} (Section 3.6): A related but distinct phenomenon -- some self-supervised ViTs' \emph{raw} last-layer attention maps happen to already highlight semantic objects well, without needing the rollout procedure, though this is an emergent property of the specific training objective (DINO) rather than a general guarantee for any ViT.
\end{itemize}

\begin{keyidea}
A key caveat, and an active topic of debate in interpretability research, is that attention weights (rolled out or otherwise) are not necessarily a fully faithful causal explanation of \emph{why} the network produced a particular output -- high attention to a region indicates that information from that region was mixed in heavily, but does not, on its own, prove that this information was the \emph{decisive} factor in the final decision. Attention rollout should be understood as a useful, principled visualization of information flow through the network's actual computation graph, rather than a definitive causal explanation.
\end{keyidea}

\section{Applications and Challenges of Advanced Visual Representation Learning}
% ============================================================

\subsection{Applications}

\begin{itemize}[leftmargin=1.5em]
    \item \textbf{Zero-shot and open-vocabulary recognition:} CLIP-style models enable classification, retrieval, and (when combined with detection/segmentation architectures) \textbf{open-vocabulary object detection and segmentation} -- recognizing object categories specified only by a text description at inference time, rather than a fixed, pre-trained label set.
    \item \textbf{Image-text retrieval and search:} Joint embedding spaces (CLIP and successors) directly support searching a large image database using a natural-language text query, or vice versa, by nearest-neighbor lookup in the shared embedding space.
    \item \textbf{Multimodal generation:} Text-to-image diffusion models (Module 5) are commonly \emph{conditioned} on CLIP text embeddings, directly connecting this module's multimodal representations to generative modeling.
    \item \textbf{Data-scarce domains:} Self-supervised pretraining (Section 3) is especially valuable in domains such as medical imaging or satellite/remote sensing, where large labeled datasets are expensive or impossible to obtain, but large amounts of unlabeled imagery exist.
    \item \textbf{Dense prediction transfer:} Foundation models such as DINOv2 provide general-purpose features that transfer well, often via simple linear probes, to depth estimation, semantic segmentation, and other pixel-level tasks, without task-specific pretraining.
    \item \textbf{Promptable segmentation:} The Segment Anything Model (SAM) and similar systems allow segmenting arbitrary, previously unseen object categories given only a simple prompt (point, box, or rough mask) at inference time.
\end{itemize}

\subsection{Core Challenges}

\begin{itemize}[leftmargin=1.5em]
    \item \textbf{Data and compute hunger:} As discussed in Section 1, ViTs trained from scratch typically require substantially more data (and/or specialized training recipes like DeiT's distillation) than CNNs to reach comparable performance, and foundation-model-scale pretraining (CLIP, DINOv2) requires web-scale data and very large compute budgets, which are inaccessible to most individual researchers or organizations.
    \item \textbf{Quadratic attention cost limits resolution:} Self-attention's $O(N^2D)$ cost (Module 3, Section 2) directly limits the number of patches (and thus image resolution) that can be practically processed, motivating research into more efficient attention mechanisms (Module 3's specialized attention variants) for high-resolution vision tasks.
    \item \textbf{Data quality and bias:} Web-scraped image-text datasets (used to train CLIP and similar models) are uncurated and can contain harmful stereotypes, offensive content, and skewed representation of different demographics or cultures, which the resulting models can inherit and reproduce in their downstream behavior.
    \item \textbf{Evaluation and contamination concerns:} Because foundation models are pretrained on enormous, often loosely-documented web-scraped datasets, it can be difficult to be fully confident that a ``zero-shot'' evaluation benchmark's images (or very similar ones) were not already present in the pretraining data, which would inflate reported zero-shot performance relative to genuinely novel data.
    \item \textbf{Interpretability remains partial:} While Attention Rollout (Section 5) provides a principled, well-motivated view into information flow, it is not a complete or fully causal explanation of model behavior, and interpretability for large, complex vision (and vision-language) foundation models remains an open, actively-researched problem.
    \item \textbf{Robustness and spurious correlations:} Learned visual representations can latch onto spurious correlations present in training data (e.g., associating an object with a typical background context) rather than the causally-relevant visual features, which can hurt generalization to distribution shifts, unusual contexts, or adversarially-crafted inputs.
    \item \textbf{Variable resolution and positional embedding limitations:} ViT's learned positional embeddings are tied to a specific number of patches (a specific training resolution); applying a pretrained ViT to images of a different resolution requires interpolating the positional embeddings, which can degrade performance if not done carefully.
\end{itemize}

\begin{keyidea}
A recurring theme across these challenges is that the same properties that make foundation vision models powerful -- learning from vast, loosely-curated, web-scale data with minimal hand-designed structure -- are also the direct source of their biggest risks (inherited bias, evaluation contamination, limited interpretability, data/compute cost). Advancing this field responsibly requires progress not just on raw benchmark performance, but on data curation, evaluation rigor, efficiency, and interpretability in tandem.
\end{keyidea}
